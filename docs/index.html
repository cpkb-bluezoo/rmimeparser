rmimeparser

Push-based MIME and RFC 5322 parsing and writing in Rust— constant memory, no message DOM, stdlib only.

Overview

rmimeparser never builds a tree of parts. Instead you implement a handler whose methods the parser calls as structure and content are recognised. The writer is the inverse: you call the same style of event methods, and encoded wire bytes stream into any std::io::Write.

  • MimeParser + MimeHandler — MIME entities, CTE decoding, multipart
  • MessageParser + MessageHandler — RFC 5322 headers on top of MIME
  • DkimMessageParser — same typed handler API, plus wire-byte accessors for DKIM
  • MimeWriter / MessageWriter — safe serialization (folding, CTE, RFC 2047)

Implementing a handler

All MimeHandler methods have default no-op bodies. Override only what you need. Return Err(...) from a callback to abort parsing.

Minimal example

use rmimeparser::{MimeHandler, MimeParser, ParseResult};

struct CountBody {
    bytes: usize,
}

impl MimeHandler for CountBody {
    fn body_content(&mut self, data: &[u8]) -> ParseResult<()> {
        self.bytes += data.len();
        Ok(())
    }
}

let raw = b"Content-Type: text/plain\r\n\r\nHello\r\n";
let mut handler = CountBody { bytes: 0 };
let mut parser = MimeParser::new(&mut handler);
let mut input = &raw[..];
parser.receive(&mut input)?;
parser.close()?;
assert_eq!(handler.bytes, 7);

Callback order

For a simple (non-multipart) entity the parser drives your handler roughly like this: 

set_locator(...)
start_entity(None)
  typed header callbacks (content_type, … / header, date_header, …)
  end_headers()
  body_content(...)       // transfer-decoded octets (may be chunked)
end_entity(None)          // from close()
CallbackWhen
set_locator Once at start; locator tracks offset / line / column for errors.
start_entity Root: None. Multipart part: Some(boundary) when that part begins.
pre_mime_header Every header before MIME-specific dispatch. Return true to skip default MIME handling for that header (used by MessageParser).
content_type Parsed Content-Type (and similarly disposition, CTE, Content-ID, description, MIME-Version).
end_headers Blank line after headers; body (or first multipart boundary) follows.
body_content Transfer-decoded body octets. May arrive in several calls—do not assume one shot. Charset decoding of text parts is left to you (see Content-Type charset).
unexpected_content Preamble/epilogue-like content where a boundary was expected.
end_entity Entity finished; multipart close uses Some(boundary).
Always prefer these typed callbacks. They deliver decoded strings and structured values. Wire-accurate capture for DKIM is a separate entry point—see DKIM / raw wire.

Feeding the parser with bytes

Call receive(&mut slice) repeatedly. The parser advances the slice past bytes it has fully consumed. Leftover bytes at the front of the slice are an incomplete line (underflow)—keep them and append the next read.

Streaming buffer loop

use rmimeparser::{MimeHandler, MimeParser, ParseResult};

fn parse_stream<R: std::io::Read, H: MimeHandler>(
    reader: &mut R,
    handler: &mut H,
) -> ParseResult<()> {
    let mut parser = MimeParser::new(handler);
    let mut buf = vec![0u8; 8192];
    let mut filled = 0usize;

    loop {
        let n = reader.read(&mut buf[filled..]).map_err(|e| {
            rmimeparser::MimeParseError::new(e.to_string())
        })?;
        if n == 0 {
            break;
        }
        filled += n;

        let mut slice = &buf[..filled];
        parser.receive(&mut slice)?;
        let remaining = slice.len();
        // Compact unconsumed bytes to the front of the buffer.
        buf.copy_within(filled - remaining..filled, 0);
        filled = remaining;
    }

    parser.close()
}
  • After receive, if parser.is_underflow() is true, more input is needed before the current line is complete.
  • For a non-multipart body, close() may succeed even with trailing underflow (end of stream). For headers or multipart, underflow on close() is an error.
  • You can also feed the entire message in one receive if it already sits in memory.
Always pass &mut &[u8] (a mutable reference to the slice). The parser rewrites the slice to the unconsumed suffix; forgetting to compact leftovers will drop or duplicate data on the next read.

RFC 5322 message parser

MessageParser wraps MimeParser. Implement MessageHandler (which extends MimeHandler) to get typed address, date, and Message-ID headers in addition to MIME callbacks. 

use rmimeparser::{MessageHandler, MessageParser, ParseResult};

struct CollectSubject {
    subject: Option<String>,
}

impl MessageHandler for CollectSubject {
    fn header(&mut self, name: &str, value: &str) -> ParseResult<()> {
        if name.eq_ignore_ascii_case("subject") {
            self.subject = Some(value.to_string());
        }
        Ok(())
    }
}

// MimeHandler methods keep their defaults unless you override them.
impl rmimeparser::MimeHandler for CollectSubject {}

let raw = b"Subject: hello\r\n\r\nHi\r\n";
let mut handler = CollectSubject { subject: None };
let mut parser = MessageParser::new(&mut handler);
let mut input = &raw[..];
parser.receive(&mut input)?;
parser.close()?;
CallbackTypical headers
header Unstructured fields such as Subject, Comments (RFC 2047 decoded).
address_header From, To, Cc, Reply-To, …
date_header Date, Resent-Date, …
message_id_header Message-ID, In-Reply-To, References, …
unexpected_header Malformed values that could not be typed.

DKIM / raw wire capture

DKIM canonicalization needs the message exactly as received (folded header bytes, undecoded body lines). That is intentionally not exposed on MimeHandler / MessageHandler.

Use DkimMessageParser instead of MessageParser. You still implement the same typed MessageHandler for decoded events. After receive / close, read wire data from the parser: 

use rmimeparser::{DkimMessageParser, MessageHandler, MimeHandler, ParseResult};

struct App;
impl MimeHandler for App {}
impl MessageHandler for App {}

let mut handler = App;
let mut parser = DkimMessageParser::new(&mut handler);
let mut input = &raw[..];
parser.receive(&mut input)?;
parser.close()?;

// Decoded events already went to `handler`.
// Wire bytes for DKIM:
let headers = parser.raw_headers();      // &[RawHeader], folds preserved
let body = parser.raw_body();            // undecoded body lines
let from = parser.raw_header("from");    // Option<&RawHeader>
Everyday apps should keep using MessageParser. Reach for DkimMessageParser only when you need canonicalization input.

Using the writer

MimeWriter and MessageWriter are push APIs—no builder or in-memory message tree. You emit events; the writer folds headers, applies RFC 2047 where needed, and CTE-encodes body chunks as they arrive. Working memory stays small (encoder scratch only).

Single part

use rmimeparser::{ContentType, MimeWriter};

let mut out = Vec::new();
let mut w = MimeWriter::new(&mut out);

w.start_entity(None)?;
w.content_type(&ContentType::new("text", "plain", None))?;
w.content_transfer_encoding("base64")?;
w.end_headers()?;

// Logical body octets — call as many times as you like.
w.body_content(b"Hello")?;
w.body_content(b" world")?;

w.end_entity(None)?;
w.close()?;
  • Declare Content-Transfer-Encoding before end_headers. Default is 7bit.
  • body_content takes logical bytes; the writer encodes to base64 / quoted-printable when those CTEs are set. For 7bit, high bytes and NULs are rejected.
  • Finish every open entity with matching end_entity, then close().

Advanced: header_raw_value / writer raw_header / raw_body_content exist to emit already-encoded wire bytes. Prefer the typed writer methods for normal construction.

RFC 5322 message writer

use rmimeparser::{
    ContentType, EmailAddress, MessageWriter, OffsetDateTime,
};

let mut out = Vec::new();
let mut w = MessageWriter::new(&mut out);

w.start_entity(None)?;
w.header("Subject", "Café")?;           // RFC 2047 as needed
w.date_header("Date", OffsetDateTime::new(2024, 6, 15, 12, 0, 0, 0))?;
w.address_header(
    "From",
    &[EmailAddress::new(Some("Ada".into()), "ada", "example.com", false)],
)?;
w.content_type(&ContentType::new("text", "plain", None))?;
w.content_transfer_encoding("quoted-printable")?;
w.end_headers()?;
w.body_content("Hello café".as_bytes())?;
w.end_entity(None)?;
w.close()?;

Multipart (parse and write)

On parse, each part is a nested start_entity(Some(boundary)) … end_entity(Some(boundary)) sequence after the parent’s end_headers.

On write, mirror that structure:

use rmimeparser::{ContentType, MimeVersion, MimeWriter, Parameter};

let mut out = Vec::new();
let mut w = MimeWriter::new(&mut out);

w.start_entity(None)?;
w.mime_version(MimeVersion::V1_0)?;
w.content_type(&ContentType::new(
    "multipart",
    "mixed",
    Some(vec![Parameter::new("boundary", "bound123")]),
))?;
w.end_headers()?;

w.start_entity(Some("bound123"))?;
w.content_type(&ContentType::new("text", "plain", None))?;
w.end_headers()?;
w.body_content(b"Part one")?;
w.end_entity(Some("bound123"))?;

w.start_entity(Some("bound123"))?;
w.content_type(&ContentType::new("text", "plain", None))?;
w.end_headers()?;
w.body_content(b"Part two")?;
w.end_entity(Some("bound123"))?;

w.end_entity(None)?; // emits --bound123--
w.close()?;
The writer refuses body_content that would embed the active multipart boundary (\r\n--boundary). Prefer base64 for binary parts under multipart.

Errors and limits

  • Parse failures use MimeParseError / ParseResult (often with locator position).
  • Write failures use MimeWriteError / WriteResult (I/O, invalid state, validation).
  • Tunables on the parser include set_max_buffer_size and set_max_header_value_size (default header value cap is 32 KiB; physical header lines must not exceed 998 octets).
